# 知识层（运行时提示词素材）

这些文件不是文档，是**每次请求要发给模型的上下文**。改这里等于改提示词。

| 文件 | 内容 | 发送方式 |
|---|---|---|
| `core_rules.md` | 基础机制：轮次 5 阶段、特使/揭示回合、战力、战斗与平局、造物主、召回、影响力同盟、控制标记、密谋时机、获取与洗牌、结束与破平 | **每次固定**（系统提示内） |
| `current_mode.md` | 本局自定义：16 分阈值、5 个内容集、4 工人、起始配置、冲突序列、AI 难度、剧本优先级 | **每次固定**（系统提示内） |
| `mechanics.tsv` | 机制索引：关键词 → 一句话 + 细节 + 来源 | **按需**，命中当前选项/局势才带（最多 3 条） |
| `examples.tsv` | 已实测的错误说法 → 正确判断 | **每次固定**（系统提示内，简短） |

## 为什么是 TSV 而不是 JSON

插件跑在 IL2CPP 运行时里，工程没有引入 JSON 库（现有的 `Json` 只做转义与取 `content` 字段）。
`mechanics.json` 需要额外的解析器与失败路径，收益为零；TSV 与项目里 `name_map.tsv` /
`effect_map*.tsv` 一致，`Split('\t')` 即可，出错也能一眼看出是哪一行。

## 分层顺序（也是缓存顺序）

```
[系统] 角色 + core_rules + current_mode + examples     ← 稳定，一字不变
[用户] 本局局势 → 命中的机制 → 本次待选列表            ← 每次都变
```

稳定内容放在系统提示里且顺序固定，DeepSeek 的上下文缓存才能命中重复前缀。
**缓存仍要发送全文**，不是服务端替我们记住规则。

## 维护约定

1. **规则与策略分开**：`core_rules.md` 只写"怎样结算"；"一般优先做什么"不进这些文件。
2. **来源必须可查**：每条机制写清规则书章节或本地化键，避免二次加工时无从核对。
3. **错误示例必须真实**：`examples.tsv` 的"错误说法"只能录实际出现过的表述。
4. **不猜数值**：细节里写"以卡面/位置文本为准"，不要在知识层编造具体数值。
5. 改完跑 `python -X utf8 -B mods/tools/verify_knowledge.py` 检查列数、来源标注与长度预算。
